# Quickstart

This page is the smallest generic setup path for trying CrateStack in a Rust service.

## 1. Include A Schema

Example schema:

```cstack
auth Principal {
  id String
  role String?
}

mixin AuditFields {
  createdAt DateTime @default(dbgenerated())
  updatedAt DateTime @default(dbgenerated())
}

model Post {
  @use(AuditFields)

  id String @id
  title String

  @@allow("read", auth() != null)
}
```

Pick the macro that matches the crate's role:

```rust
// Server crate
use cratestack::include_server_schema;

include_server_schema!("schema.cstack", db = Postgres);
```

`db = Postgres` is the argument for a schema with a real `datasource { provider = "postgresql" }` block. A schema declaring `datasource { provider = "none" }` instead pairs with `db = None` — see [Procedures-only servers](#procedures-only-servers-no-database) below. The two must agree: passing `db = Postgres` against a `provider = "none"` schema (or vice versa) is a compile-time macro error, not a runtime one.

Embedded (mobile / desktop / browser-via-OPFS) and HTTP-client crates use different macros — see [Offline-First Embedded SQLite](../guides/offline-first-sqlite) and the client-runtime docs respectively.

## 2. Build The Generated Runtime

```rust
let pool = sqlx::PgPool::connect(&std::env::var("DATABASE_URL")?).await?;
let cool = cratestack_schema::CrateStack::builder(pool).build();
```

## 3. Use Delegates Directly

You can use CrateStack without mounting the generated REST layer.

```rust
let visible_posts = cool
    .post()
    .find_many()
    .where_expr(
        cratestack_schema::post::author()
            .email()
            .eq("owner@example.com")
            .and(cratestack_schema::post::published().is_true()),
    )
    .order_by(cratestack_schema::post::author().email().desc())
    .limit(20)
    .run(&ctx)
    .await?;
```

## 4. Optionally Bind Auth For Internal Callers

```rust
let bound = cool.bind_auth(Some(serde_json::json!({
    "id": 7,
    "role": "admin"
})))?;

let posts = bound.post().find_many().run().await?;
```

## 5. Optionally Mount Generated Routers

```rust
let app = axum::Router::new().nest(
    "/api",
    cratestack_schema::axum::model_router(
        cool.clone(),
        cratestack_codec_cbor::CborCodec,
        AppAuthProvider,
    ),
);
```

## Procedures-only servers (no database)

Not every server owns a database. A pure RPC/REST facade in front of another service, a stateless computation endpoint, or a gateway that only validates and forwards requests has no models to persist. For that shape, declare `datasource { provider = "none" }` instead of a real Postgres datasource:

```cstack
datasource db {
  provider = "none"
}

type PingArgs {
  message String
}

type PingReply {
  echo String
}

procedure ping(args: PingArgs): PingReply
  @allow(auth() != null)
```

A `provider = "none"` schema can **never** declare a `model` block — the parser rejects it at check time, not at runtime. This mode is for procedures and business logic only, typically calling out to your own existing systems.

Pair it with `db = None` at the call site:

```rust
use cratestack::include_server_schema;

include_server_schema!("schema.cstack", db = None);
```

Under `db = None`, `Cratestack::builder()` takes **zero arguments** — there's no `PgPool`, no connection string, and no `Option<PgPool>` standing in for one. `Cratestack` itself is a zero-field marker type; procedure dispatch and `@allow` policy evaluation work exactly as they do under `db = Postgres` (neither ever touched the database connection to begin with):

```rust
let db = cratestack_schema::Cratestack::builder().build();
let app = cratestack_schema::axum::router(db, Procedures, JsonCodec, AllowAllAuth);
```

Two facade crates support this mode:

* `cratestack = { package = "cratestack-api" }` — the dedicated no-database facade. It has no `cratestack-sqlx` dependency at all, under any Cargo feature, so a `db = Postgres` schema fails to compile against it with a clear error rather than a wall of unrelated symbol-resolution errors. Recommended for new procedures-only services.
* `cratestack = { package = "cratestack-pg", default-features = false }` — turns the `postgres` Cargo feature off, which drops `sqlx`/`cratestack-sqlx` from the dependency graph the same way. Still fully supported; not deprecated in favor of `cratestack-api`.

Both are genuinely `sqlx`-free — this used to be a known gap (an earlier `db = None` consumer still compiled `sqlx` in unconditionally), tracked as [issue #329](https://github.com/cratestack/cratestack/issues/329), which has since shipped alongside the `cratestack-api` facade ([issue #347](https://github.com/cratestack/cratestack/issues/347)).

See `crates/cratestack-pg/tests/no_database_procedures.rs` in the framework repo for a full worked example, and [epic #326](https://github.com/cratestack/cratestack/issues/326) for the design history.
